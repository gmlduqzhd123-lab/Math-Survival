# 모바일·태블릿 검증 — 2026-10-09

로컬 2.1 개발본을 Windows에서 Chromium(Edge) 및 WebKit 엔진의 터치 화면 에뮬레이션으로 검사했다. GitHub Pages 배포본 검사가 아니며 이번 수정은 원격에 게시하지 않았다.

최종 결과는 9개 화면 크기 × 2개 엔진, 18/18 통과다. 모든 환경에서 런타임 예외와 HTTP 자산 오류는 0건이었다.

## 화면 범위

각 화면을 두 엔진에서 검사하고, 게임 실행 중 가로·세로 크기를 서로 바꿔 회전도 검사한다. 화면 크기는 CSS 픽셀이다.

| 화면 | 크기 | DPR |
|---|---|---|
| 작은 휴대폰 | 320×568 | 2 |
| Android 크기 | 360×640 | 3 |
| iPhone 크기 | 390×844 | 3 |
| 큰 휴대폰 | 430×932 | 3 |
| 휴대폰 가로 | 844×390 | 3 |
| 태블릿 세로 | 768×1024 | 2 |
| 큰 태블릿 세로 | 820×1180 | 2 |
| 태블릿 가로 | 1024×768 | 2 |
| Android 태블릿 가로 | 1280×800 | 2 |

## 검사 내용과 수정

- 큰 글자 설정, 문제·해설·답안·보스 체력·조작 영역의 배치, 페이지 넘침, 주요 터치 버튼 최소 44px, Canvas DPR 대응.
- 탐험에서 터치로 오답·정답 선택, 오답 피해 없음, 해설 중 시간 정지, 목표 종료와 정확도, JSON 실제 다운로드, 재로딩 후 기록 보존.
- 서바이벌 대시·스킬·일시정지·재개, 실행 중 화면 회전 후 입력 초기화, 보스 화면과 중단 결과.
- Chromium에서는 실제 CDP 터치 드래그·취소와 이동을 확인했다. WebKit에서는 신뢰된 터치 탭과 해제만 확인했으며 연속 드래그 검증은 포함하지 않는다.
- 첫 프레임 이후 Canvas 픽셀 렌더링, 런타임 예외와 HTTP 오류 자산이 없는지 확인한다.

Windows용 WebKit 환경에는 AudioContext가 없어 게임 시작이 예외로 중단됐다. `src/ui.js`에서 API 부재·생성 거부 시 무음으로 진행하고 재개 Promise 거부를 처리하도록 수정했다. 별도 단위 검사로 API 부재·생성 거부·재개 거부를 검증했다. 이 환경의 제한을 실제 iPhone Safari 오류로 단정하지 않는다.

## 증거와 재현

- [18개 환경 검사 결과](mobile-tablet-verification/report.json): 엔진 버전, 개별 검사, 배치 수치, 오류 목록.
- 같은 폴더의 `*-play.png`, `*-rotated.png`는 초기·회전 화면이며 `*-result.json`은 실제 다운로드 결과다.
- `npm start` 실행 후 `npm run test:devices`. WebKit은 최초에 `npx playwright install webkit` 설치가 필요하다.
- 기존 브라우저 회귀 검사 30개, 기존 단위 검사 46개 및 새 오디오 검사 1개, 정적 빌드가 통과했다. 보존용 원본 HTML의 SHA256은 기존과 동일하다.

실물 Android·iPhone·iPad의 브라우저 주소창 변화, 안전 영역, 실제 Safari 저장·다운로드 정책, 장시간 발열·프레임 성능, 소리 재생은 이번 검사로 인증하지 않는다. 휴대폰과 태블릿의 화면 배치·주요 게임 흐름은 에뮬레이션 범위에서 확인했다.
