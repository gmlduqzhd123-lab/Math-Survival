# 이동 렉 수정 — 2026-10-09

큰 게임 화면에서 고해상도 Canvas를 매 프레임 다시 그리고, 카메라 이동 중 회전된 배경 이모지를 계속 렌더링하고, 같은 HUD 글자를 초당 약 60회 교체하는 비용을 줄였다.

- 화면의 CSS 크기와 게임 좌표·이동 속도는 유지한다. Canvas 내부 해상도는 약 300만 픽셀 예산과 기기 DPR 중 작은 값으로 결정한다. 회전·리사이즈 시 다시 계산한다. 작은 휴대폰 화면은 DPR 3을 유지한다.
- 배경 장식은 회전된 그림을 한 번 만들고 이후 재사용한다. 지도 변경 시 새 장식이 생성되고 해상도 변경 시 캐시를 다시 만든다.
- 같은 HUD 값은 DOM에 다시 쓰지 않는다. 격자 선을 한 경로로 그리고, 불투명한 배경 앞의 불필요한 Canvas 지우기를 제거한다.

## 측정

Windows Edge headless, 1920×1080/DPR 3 및 390×844/DPR 3, 시드 42, 서바이벌 모드에서 준비 이동 후 왼쪽 6초·아래쪽 6초를 입력했다. 적과 공격은 켜 둔 상태이고 생존 검증을 위해 HP를 크게 설정하고 경험치를 낮춰 성장 선택창이 열리지 않게 했다. 별도 RAF로 프레임 간격을 측정했다. 실제 사용자 장치의 성능 보장은 아니다.

두 데스크톱 측정의 CSS 게임 영역은 각각 1904×694 및 1904×765였다. 측정된 게임 영역 크기가 달라 완전히 동일한 픽셀 크기 비교는 아니다. 두 측정 모두 게임 시계가 약 12초 진행했으며 성장 선택창으로 멈춘 구간은 없다. 수정 후 영역이 더 크면서도 프레임 간격이 줄었다. 픽셀 수는 정수 반올림으로 예산보다 소폭 높을 수 있다.

`npm run test:movement`는 현재 빌드에서 실제 이동·키 해제·실행 상태·런타임 오류·픽셀 예산·HUD 변경량을 검증하고 `test-results/movement/`에 측정과 화면을 저장한다. CI 환경에 따른 타이밍 변동 때문에 FPS 수치 자체는 통과 기준으로 사용하지 않는다.
